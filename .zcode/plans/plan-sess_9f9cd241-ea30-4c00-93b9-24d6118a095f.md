# 重新设计：让 Agent 完全自主，不再需要人确认/手选

## 目标
把「人来点确认、人来选文件」的每一步都删掉，改为：Agent 自己在授权范围内查阅、执行；人类不再出现在执行路径里。按你的选择，**文件不设边界（整盘可读写）**，只保留纯技术护栏（UNC/符号链接拒绝、纯文本、大小上限）。

---

## 二、文件能力改造（`plugins/files.rs` + `files_plugin.rs`）

把「选择器」换成「模型自己给路径」，并**新增自主浏览能力**（截图里扫不了目录就是因为缺这些）：

- **`files.read`**（改）：`{ path: string }` — 直读；保留纯文本白名单、128 KiB 上限、BOM 处理、`untrusted:true`。
- **`files.create_text`**（改）：`{ path, content, overwrite?: bool }` — 直写；默认不覆盖，`overwrite:true` 时原子覆盖（否则 Agent 无法改自己写的文件）。保留扩展名/保留名/大小校验。
- **`files.list`**（新，L0）：`{ path, depth?: 1..3 }` — 列目录，返回 `{name,path,kind,size}`，封顶 500 条。
- **`files.search`**（新，L1）：`{ path, pattern, contentMatch?: bool, maxResults?: 1..200 }` — 按文件名匹配，可选按内容匹配（仅文本、限大小），返回命中路径 + 行号/片段。

保留 `guard_selected` 的技术护栏（绝对路径、拒 UNC、拒符号链接），这是你选的「技术护栏」。

## 三、新增通用启动能力（`system` 插件）

- **`system.launch_app`**（新，L1）：`{ name?: string, path?: string, args?: string[] }`，二选一：
  - `path` = 绝对路径：`.exe/.bat/.cmd/.com` 直接 `Command::spawn`；`.lnk/.url/其他` 走 shell 关联（`tauri_plugin_opener`，已装 2.5.5）。
  - `name` = 友好名：扫描开始菜单 `%ProgramData%\...\Start Menu\Programs` 与 `%APPDATA%\...\Start Menu\Programs` 的 `.lnk`（大小写不敏感包含匹配），命中则启动；未命中返回明确错误。
- 启动本身不再弹确认。`computer` 插件的 `guard::blocked`（终端/浏览器/提权窗口拒绝）**保留**——那是 UIA 输入的安全边界，不是确认框。

## 四、清掉「审批」这套已经名存实亡的脚手架

`requires_confirmation` 从此是一句谎话，删除它，让不变式真实：

- Rust 结构：`ToolExposure`、`ToolStatus`、`ToolDefinition` 三个字段删除；各插件清单里 ~14 处 `requires_confirmation: ...` 删除。
- `permissions.rs` 精简为仅 `RiskLevel` + `args_hash`（二者仍被风险徽章与轨迹使用）；删除 `PermissionPolicy`、`ApprovalSnapshot` 及其测试。
- 删除命令 `agent_preview_approval`、`AgentState.pending_approvals`，并在 `lib.rs:146` 的 `generate_handler!` 移除注册。
- 删除死代码 `src/components/agent/ApprovalCard.tsx`（无任何引用）。
- `approvals` 数据表保留（无迁移风险，仅不再写入）。

## 五、提示词与前端文案

- `model.rs:100` 去掉「需要确认的操作必须等待用户确认；用户拒绝后停止该操作，不换工具绕过拒绝。」改为：自主完成、失败如实报告、不伪造结果。（保留「普通问候」等被测试断言的句子）
- `Settings/components/PluginCatalog.tsx:20` 文案「高风险操作仍会在执行前请求确认」→ 改为说明自动执行 + 技术护栏。
- `src/agent/plugins/types.ts` 删除 `ToolStatus.requiresConfirmation`。

## 影响面小结
- 改动文件：约 16 个 Rust 文件（插件 6、agent 核心 5、computer/netease 3）、3 个前端文件、2 个测试文件；删除 1 个前端组件。
- 安全模型：从「逐次人工确认」改为「无边界 + 技术护栏 + 事后审计（`agent_events`/`runs` 照旧留痕）」。
- 不新增设置页（无边界后没有可配项）；权限分区维持现状文案。

风险提示：文件不设边界 + 通用启动意味着 Agent 可读写任意本机文件、启动任意程序。`is_text_path`/大小/UNC/符号链接护栏仍在，但这是刻意的强能力模型。
